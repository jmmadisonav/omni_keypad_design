User guide.

Design button images for an OMNI keypad, and deploy them to it.

Each button has an OFF and an ON image, and optionally an ALT image. You design each of these states on its own. The designer draws the images at the size your keypad needs, so you lay out buttons the same way on every model. The designer runs on your computer and doesn't need internet access.

Get started

You need a keypad that runs firmware 1.1.x on your network. Deploying uploads the whole design to the keypad.

To start the designer, open OMNI Keypad Designer from the Start menu. The first time, it opens a new project called "Untitled". After that, it opens your most recent project.

The window has four areas:

  • The header shows the project name, the keypad's IP address, and the Find, Import, Backups, Locate, and Deploy buttons.
  • The keypad view shows the page you're working on, with the page tabs above it and the keypad model just above the keypad.
  • The States rail shows the OFF, ON, and ALT images of the selected button.
  • The sidebar has the Keypad, Page, Button, and Library tabs.

The menu bar holds the project commands:

  • File: New Project, Open Project, Save, Save As, Open Data Folder, and Exit.
  • Edit: Undo and Redo, plus Cut, Copy, Paste, and Select All for text fields.
  • View: Reload, zoom, Full Screen, and Developer Tools.
  • Keypad: Locate, Back Up Keypad Now, and Factory Reset, for the keypad whose IP address is in the header.
  • Help: this guide, and About, which shows the app's version.

Design a button

  1. To start a project, click File > New Project, and choose its name and keypad model. To work on a keypad's current design instead, enter its IP address in the header, or click Find, and then click Import. That saves the design as a new project named after the keypad, for example 172-17-0-55 2026-10-06.
  2. Click a button on the keypad view. The States rail shows its OFF, ON, and ALT images.
  3. Click a state in the rail to edit it. The keypad shows that state on every button, and the Button tab shows that state's parts.
  4. Turn parts on with their switches, and click a part to change it.

Each state is built from four parts, drawn from back to front:

  • Background: a base shape (Squared, Bubble, or Circle 45) in a Keypad Graphics colour, or a colour of your own.
  • Image: a PNG or SVG of your own, such as a logo. It fills the button and covers the background.
  • Icon: any of more than 1,800 icons.
  • Text: one or two lines in Titillium Web, Inter, Roboto, or Oswald.

Each state keeps its own settings, so ON can have a different icon, colour, or text from OFF. A part that differs from OFF is marked ≠ OFF. New parts start the same in every state: a dim blue background, and white icons and text.

To move the open part, drag it on the selected state in the rail, or change X and Y.

Choose a background colour

Most Keypad Graphics colours come as a dim and a bright picture. To use dim, click the left half of a swatch. To use bright, click the right half. You choose this for each state.

To use your own colour, click + after the swatches, and pick Dim or Bright. The designer recolours the shape's grey artwork, so it keeps its shading.

Copy a state

To make another state of this button match the one you're editing, click Copy state and choose the state. To copy to another button, choose Copy the … state to another button or Copy all states to another button, and then click that button. You can switch pages first. The other button keeps its name and page link.

Rename a button

To rename a button, double-click its name at the top of the Button tab, type the new name, and press Enter. To keep the old name, press Esc. The name also names the button's image files on the keypad, for example HDMI_1_OFF.png.

Swap two buttons

To swap two buttons, drag one onto the other. The artwork, name, and page link move. Control settings, such as the HControl path, stay with each position. To show another page while you drag, drag over that page's tab.

Save and deploy

A red square marks each button you've changed since you last saved. A red square next to the project name means the project has unsaved changes.

  • To save, click File > Save, or press Ctrl+S. You don't need a keypad to design or save.
  • To keep a copy under another name, click File > Save As.
  • To open another project, click File > Open Project, and choose it.

To put the project on a keypad, enter the keypad's IP address in the header and click Deploy. The designer saves first if it needs to. The keypad restarts with the project in about 20 seconds.

Before it uploads, the designer checks the keypad's model. If it isn't the project's model, nothing is uploaded. If the keypad has a different design from the one this project last imported or deployed, the designer asks before it replaces it.

Undo a change

To undo a change, press Ctrl+Z or click Edit > Undo. To redo it, press Ctrl+Y. You can undo every change since you last saved or opened the project. In a text field, Ctrl+Z undoes your typing in that field instead.

The ALT state

Each button can have a third state, ALT. A control system sets it over HControl with "value":"Alt" on the button's state path. Most designs don't use it, so a button has no ALT state until you add one.

To give a button an ALT state, do the following:

  1. Select the button, and click + Add ALT in the States rail.
  2. Click Start from OFF, Start from ON, or Start blank.
  3. Change ALT's parts. They're separate from OFF and ON.

To take a button's ALT image off the keypad, click Remove ALT under its ALT image, and then save and deploy. Import keeps the ALT images a keypad already has.

Layers

Simple shows one of each part. When a button needs more, such as two text labels or a second icon, click Layers next to the button name. Layers shows the state's layers in two groups:

  • Front holds Text and Icon layers. They're see-through, so you can have any number, in any order.
  • Back holds Shape and Image layers. They're solid, and they always draw behind Front.

When one Back layer hides another, a warning explains what's hidden, and offers to delete the hidden layer or, for an image, to shrink it. You can switch back to Simple when every state has at most one of each part.

Pages

The tabs above the keypad view show the design's pages. A design can have up to 9 pages.

  • To add a page, click + Page. A new page has page 1's background colour and dial and LED ring settings, blank ranges, and no button images.
  • To rename a page, double-click its tab. Page names must be unique. Buttons that switch to the page keep switching to it.
  • To delete the page you're viewing, click × on its tab. Buttons that switch to it stop switching pages.

To make a button switch pages, select the button, and then choose a page in Go to page. The keypad switches pages by itself, without a control system. A badge such as → Lights marks each button that switches pages.

Note: HControl paths use page numbers, such as /page3/button1/action. Deleting a page moves the pages after it up one number, so update any control system that uses their paths.

Keypad and page settings

The Keypad tab holds settings for every page. The Page tab holds settings for the page you're viewing. Opening either tab deselects the selected button. These settings are saved with the project, deployed with it, and undone with Ctrl+Z.

On the Keypad tab, Lines sets the colour of the lines between buttons.

On the Page tab:

  • Background sets the page's background colour. It shows as a thin border around the buttons, and behind blank buttons and the transparent parts of button images.
  • Dial range and LED ring range set the lowest and highest level of the dial and the LED ring, separately. Use whole numbers; they can be negative. To use the keypad's own range, 0 to 200, leave both boxes blank. These settings only appear on models with a dial.
  • Bindings on this page lists controls that are bound to an OMNI device or use a script reference.

Housing and finish

Under the keypad view, Wall | Tabletop sets the housing, and Black | White sets the finish. The finish only changes the preview. Both are saved with the project straight away.

OMNI bindings and script references

A design made in AVX can bind controls to an OMNI device. A bound control isn't available over HControl. When a project has bound controls, a warning above the keypad says how many, and the Page tab lists them.

To make them available over HControl, click Remove OMNI bindings on the Page tab, and then save and deploy. This applies to every page. Page links and script references stay, and the dial and LED ring go back to the keypad's own range.

A control can also use an AVX script reference, such as Category_1/Reference_1. It's still available over HControl, but at the reference's path instead of its page's path. For example, a dial on that reference is at /Category_1/Reference_1/level instead of /page1/dial/level. To move the controls back to their page paths, click Remove script references, and then save and deploy.

The library

To keep a button's design so you can reuse it, click Save to library and give it a name. To use it, open the Library tab, and then click the design to apply it to the selected button, or drag it onto any button. Applying a design replaces the button's parts and name, and keeps its page link. Buttons that use the same design share the same image files on the keypad.

Ready-made on the Library tab shows finished buttons from Keypad Graphics.

Backups

The designer keeps a copy of a keypad's design before it changes it:

  • Every deploy saves the design that was running first.
  • Every Import saves a copy of what it imported.
  • Back up keypad now in Backups saves a copy whenever you like.
  • Factory Reset saves a copy first, unless you clear its checkbox.

To put a design back, click Backups, choose a backup, and click Restore. Restoring works even when the keypad has no design. If a deploy fails after its backup, the designer offers to restore that backup.

Locate or reset a keypad

To see which keypad has the IP address in the header, click Locate. The keypad's LED ring cycles for about 8 minutes. To stop it sooner, click Stop locating. The button changes back by itself when the keypad stops. Keypad > Locate does the same.

To reset a keypad to its factory settings, do the following:

  1. Enter the keypad's IP address in the header, or click Find.
  2. Click Keypad > Factory Reset.
  3. To keep a copy of the keypad's design, leave Back up the keypad's design first selected.
  4. Click Factory reset.

The keypad loses its design and restarts. If it had a fixed IP address, it might come back with another one; to find it, click Find. To put the design back, deploy a project or restore the backup.

Program the keypad from your own code

The HControl drawer under the keypad view shows the strings your own code sends to the keypad and the replies to expect. To see them for a button, select the button. They cover subscribing to presses, getting and setting the button's state, and enabling or disabling it. Models with a dial also show the dial and LED ring paths. The Notes pane explains the protocol rules.

  • To copy one line, point to it and click its copy button.
  • To copy every line, click Copy all.
  • To resize the drawer, drag its top edge. To hide or show it, click the selected tab.

Try a design on the keypad

The Debug tab answers the keypad the way a simple control system would, so you can check a deployed design by hand. It doesn't need a project open.

  1. Enter the keypad's IP address in the header, or click Find.
  2. Click the Debug tab, and then click Connect.
  3. Press buttons and turn the dial on the keypad.

While you're connected, pressing a button switches it between OFF and ON, and turning the dial sets the LED ring on the same page to the dial's level. The log shows every line sent (→) and received (←). When you connect, the log lists any controls the keypad doesn't make available; they might be bound to an OMNI device. Deploying closes the connection. To start again, click Connect.

Troubleshooting

The app saves to AppData instead of Documents

If Windows doesn't let the app save to Documents, for example because Windows Security's Controlled folder access is on, the app keeps your files in %APPDATA%\OMNI Keypad Designer\Data and tells you once. If you later let the app and its python.exe through Controlled folder access, it goes back to Documents, and you can move anything you saved in the meantime across.

A project says its model file is missing

You can still edit the project, but you can't deploy it until the model file is back. To restore it, reinstall the app.

The keypad has no design

A keypad with no design, for example after a factory reset, doesn't need a backup. Deploy checks for a design for about 15 seconds, and then uploads the project anyway.

A button from an earlier version lost its parts

The designer only opens button designs made since the States rail, where each state has its own parts. A button saved by an earlier version opens with the images it has on the keypad, as an image in each state. A library design from an earlier version can't be applied; to remove it, delete it from the library.
