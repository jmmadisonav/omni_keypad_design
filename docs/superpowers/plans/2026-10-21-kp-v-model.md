# OMNI-KP-V Support Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let the designer create, import, edit, debug, and deploy projects for the OMNI-KP-V, a keypad with a knob, push button, and LED ring and no buttons or screen.

**Architecture:** A new model file describes the KP-V as a zero-button, one-page, dial model with a `knob` faceplate. The model loader, import, and backup matching learn two general rules from the model file: `max_pages`, and "a zero-button model holds no buttons". The editor switches to a knob-only mode whenever the model has no buttons. That mode hides everything button- or page-related and opens on the Page tab's dial ranges.

**Tech Stack:** Python 3 standard library (`unittest`), vanilla ES modules (`node:test`), CSS.

**Spec:** `docs/superpowers/specs/2026-10-21-kp-v-model-design.md`

## Global Constraints

- Model ID `OMNI-KP-V`, display name `V`. There are no aliases and no tabletop housing.
- A KP-V project has exactly one page.
- Behaviour comes from model-file fields, never from comparing to the string `OMNI-KP-V`.
- The 6B, 6BV, and 8BV must behave exactly as before. Every existing test still passes, apart from the ones this plan changes.
- Hidden settings (`display`, `haptic`, `pin`) stay in the design file unchanged.
- Never run `git push`.
- Python tests: `.venv/Scripts/python.exe -m unittest discover -s tests -t .`. Frontend tests: `npm run test:designer`.
- Comments and user-facing text follow the Google developer documentation style: second person, active voice, present tense.

## Review Focus

1. **An import from a KP-V holding two pages:** refused with a message naming the problem, and no project is created. Pinned in Task 2.
2. **An imported KP-V design keeps its `display.panel_separator_color` (`#DFDFDF`) and bindings through save and deploy unchanged:** pinned in Task 2.
3. **A new KP-V project sent with `housing: "tabletop"`, for example from a remembered choice:** stored as `wall`. Pinned in Task 2.
4. **Debug on a design with only dial controls:** prompts "Turn or press the dial." Pinned in Task 2.
5. **Switching from a KP-V project to an 8BV project:** brings back every hidden tab, the rail, the page tabs, and the housing toggle. Checked by hand in Task 4, Step 6.
